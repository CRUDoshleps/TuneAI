# Роли и права

TuneAI разделяет обычное прохождение assessment и администрирование платформы.

## Роли

| Роль | Что видит | Что может делать |
| --- | --- | --- |
| `student` | Свои тренировки и назначенные тесты | Проходить тесты, отправлять голосовые или текстовые ответы, смотреть свои результаты |
| `examinee` | Только назначенные экзамены | Проходить вопросы последовательно, получать результат после обработки |
| `candidate` | Только назначенные интервью | Отвечать на вопросы и смотреть результат, если это разрешено процессом |
| `methodist` | Свои тесты, материалы, скиллы и управляемых пользователей | Создавать assessment, вопросы, RAG-материалы, AI-скиллы, назначать свои тесты своим пользователям |
| `teacher` | Свои учебные тесты и ответы | Создавать тесты, назначать их своим пользователям, проверять ответы вручную |
| `interviewer` | Свои интервью и кандидатов | Создавать интервью, назначать их кандидатам, проверять ответы |
| `admin` | Весь инстанс | Управлять пользователями, ролями, группами, тестами, материалами, AI-провайдерами и ошибками обработки |

## Авторизация

Обычные пользователи входят через публичный вход:

```text
POST /auth/login
```

Администраторы входят через отдельный endpoint:

```text
POST /auth/admin/login
```

Первый администратор создается через `/auth/admin/register`. После этого самостоятельная регистрация администраторов закрывается. Новых сотрудников создает действующий администратор.

## Пользователи и группы

Администратор может создать пользователя в админке и выдать ему логин с паролем. Методист, преподаватель или интервьюер может создавать управляемых пользователей, если роль разрешена политикой приложения.

Группы нужны для курса, класса, потока или набора кандидатов. Тест можно назначить одному пользователю или всей группе. При групповом назначении уже назначенные пользователи пропускаются.

## Видимость тестов

Пользователь видит тест, если выполняется одно из условий:

- он владелец теста;
- он администратор;
- тест назначен ему напрямую;
- тест назначен группе, где он состоит.

Для студента, экзаменуемого и кандидата будущие вопросы не раскрываются заранее. В попытке API возвращает только текущий доступный вопрос и уже открытые вопросы.

## Настройка прав через `.env`

```env
TEST_CREATOR_ROLES=student,methodist,teacher,interviewer,admin
ANSWER_REVIEWER_ROLES=teacher,interviewer,admin
```

`TEST_CREATOR_ROLES` определяет, кто может создавать тесты, вопросы, RAG-материалы и AI-скиллы.

`ANSWER_REVIEWER_ROLES` определяет, кто может открывать очередь ручной проверки и менять итоговую оценку ответа.

## Ручная проверка

Ручная проверка нужна, если AI вернул низкий confidence, обнаружил проблемы с опорой на источники или преподаватель хочет изменить итоговый балл. Ручной итог сохраняется отдельно от AI-оценки и пересчитывает общий результат попытки.
