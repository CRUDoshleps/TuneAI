# RAG

TuneAI поддерживает материалы с разной областью видимости:

- весь тест;
- отдельный вопрос.

Во время проверки RAG использует:

- общие материалы теста;
- материалы, привязанные к текущему вопросу.

Материалы, привязанные к другим вопросам, исключаются.

## Процесс

1. Материал загружается в систему.
2. Материал получает статус `pending`.
3. Backend создает outbox-событие для worker-процесса.
4. Worker разбивает текст на чанки и считает embeddings.
5. После успешной обработки материал получает статус `indexed`.
6. Если индексация упала, материал получает статус `failed` и текст ошибки.

Во время проверки ответов RAG использует только материалы со статусом `indexed`. Материалы в статусах `pending` и `failed` не попадают в контекст.

Дальше при обработке ответа:

1. Система векторизует вопрос и расшифровку ответа.
2. Cosine search возвращает релевантный контекст.
3. YandexGPT получает ответ, критерии и контекст в защищенной обертке.

Текущая реализация хранит embeddings как JSON и считает cosine similarity в Python. Следующий production-шаг - перенести поиск на `pgvector`.
