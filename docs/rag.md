# RAG-материалы

RAG нужен, чтобы проверка опиралась на учебные материалы, а не только на общий ответ модели.

## Где можно хранить материал

| Scope | Когда использовать |
| --- | --- |
| `organization` | Общие правила, стандарты или база знаний организации |
| `course` | Материалы курса, которые подходят нескольким тестам |
| `test` | Материалы только для одного assessment |
| `question` | Материал нужен только для конкретного вопроса |

Для `question` обязательно укажите `test_id` и `question_id`. Для `course` нужен `course_id`. Для `organization` нужен `organization_id`.

## Поддерживаемые файлы

Материалы можно создать текстом через API или загрузить файлом. Поддерживаются TXT, Markdown, PDF и DOCX. После загрузки backend сохраняет исходный файл, а worker готовит индекс.

## Статусы индексации

| Статус | Что происходит |
| --- | --- |
| `uploaded` | Файл или текст сохранен |
| `parsing` | Worker извлекает текст |
| `chunking` | Текст делится на фрагменты |
| `embedding` | Для фрагментов считаются embeddings |
| `indexed` | Материал готов к поиску |
| `failed` | Индексация не прошла, ошибка лежит в `index_error` |

В оценку попадают только материалы со статусом `indexed`.

## Политика материалов в тесте или AI-скилле

| Policy | Какие материалы брать |
| --- | --- |
| `test_and_question` | Материалы теста и текущего вопроса |
| `question_only` | Только материалы текущего вопроса |
| `course_library` | Материалы курса |
| `organization_library` | Материалы организации |
| `none` | Не использовать RAG |

Эту политику можно задать в настройках теста или AI-скилла. Для экзамена обычно подходит `test_and_question`. Для общей подготовки по курсу подходит `course_library`.

## Как RAG используется при проверке

1. Worker получает вопрос и ответ пользователя.
2. Система формирует поисковый запрос из текста вопроса и ответа.
3. Подходящие chunks выбираются по embeddings и cosine similarity.
4. AI-проверяющий получает вопрос, ожидаемый ответ, критерии, ответ пользователя и найденные фрагменты.
5. В результате сохраняются score, feedback, confidence и `source_excerpts`.

Ответ пользователя, ожидаемый ответ и найденный контекст считаются недоверенными данными. Модель получает их в защищенной обертке, а системные инструкции отделены от пользовательского текста.

## Генерация вопросов из RAG

Конструктор может предложить вопросы по индексированным материалам.

```text
POST /tests/{test_id}/generate-questions
```

Запрос задает:

- `material_policy`;
- количество вопросов;
- максимальное число chunks;
- token budget;
- разрешение переиспользовать уже найденные похожие вопросы.

Система выбирает разнообразные chunks через MMR-подход: учитывает качество фрагмента и штрафует слишком похожие фрагменты. Для одинакового набора материалов и настроек используется fingerprint-кэш. Это уменьшает повторную генерацию одинаковых вопросов и снижает расход токенов.

Сгенерированный вопрос по умолчанию получает `answer_mode=both`. Преподаватель может изменить формат ответа при добавлении вопроса в тест.

## Текущие ограничения

Embeddings хранятся как JSON, а поиск считается в Python. Для больших production-инсталляций следующий шаг - перенести поиск на `pgvector`.
