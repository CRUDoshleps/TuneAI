# TuneAI: план подготовки к студенческому опен-коллу и конференции

## 1. Продуктовая идея

TuneAI — не автоматическая замена преподавателя и не «черный ящик», который просто ставит балл. Это тренажер устного ответа с опорой на материалы курса:

1. студент отвечает голосом;
2. Yandex SpeechKit превращает запись в текст;
3. Yandex Text Embeddings находят релевантные фрагменты учебных материалов;
4. YandexGPT сопоставляет ответ с вопросом, рубрикой и найденными источниками;
5. TuneAI показывает расшифровку, раскрытые тезисы, пробелы, рекомендации, использованные источники и уровень уверенности;
6. при недостаточной уверенности система рекомендует проверку преподавателем.

Основной конкурсный сценарий — самостоятельная подготовка студента к устному экзамену или защите лабораторной работы. Закрытый экзамен и профессиональное интервью остаются дополнительными сценариями, показывающими расширяемость платформы.

## 2. Что должно быть доказано на конкурсе

- Работает полный путь от микрофона до объяснимого отчета.
- В продукте явно и проверяемо используются SpeechKit, YandexGPT и Text Embeddings.
- Обратная связь опирается на материалы курса, а источники видны пользователю.
- Низкая уверенность модели не маскируется: система просит преподавателя проверить результат.
- Роли студента, преподавателя и экзаменуемого имеют разные права и сценарии.
- Прототип воспроизводимо запускается, проходит автотесты и production-сборку.
- Есть сценарий живой демонстрации, который не зависит от ручной подготовки данных во время выступления.

## 3. Реализация conference-ready версии

### P0 — обязательно до подачи

- [x] Добавить прозрачный статус интеграции AI Studio: mock/real, настроенные инструменты, предупреждение о демонстрационном режиме.
- [x] Добавить в результат оценки фрагменты источников, grounded-флаг, версию рубрики и рекомендацию ручной проверки.
- [x] Ограничить некорректный балл модели диапазоном `0..max_score`.
- [x] Переработать экран результата: сильные стороны, ошибки, пробелы, следующий шаг, уверенность, источники и human-in-the-loop.
- [x] Усилить первый экран формулировкой образовательной ценности и прозрачным AI-пайплайном.
- [x] Добавить тесты новых гарантий и endpoint готовности.
- [x] Подготовить воспроизводимый демонстрационный датасет.
- [x] Замкнуть human-in-the-loop: очередь спорных ответов, решение преподавателя и показ итогового комментария студенту.

### P1 — пилот перед конференцией

- [ ] Проверить реальные вызовы AI Studio минимум на 10 аудиозаписях.
- [ ] Собрать 30–50 ответов и двойную оценку преподавателя.
- [ ] Измерить согласованность баллов, полезность обратной связи, задержку и стоимость обработки.
- [ ] Зафиксировать спорные случаи: плохой звук, очень короткий ответ, фактическая ошибка, ответ вне материалов.
- [ ] Развернуть HTTPS-стенд и записать резервное видео полного сценария.

### P2 — развитие после MVP

- Yandex AI Assistant API и Search Index для управляемого RAG с нативными citations.
- Индекс pgvector или гибридный Search Index вместо полного перебора векторов.
- PDF/DOCX с метаданными страницы и раздела в каждом показанном источнике.
- Потоковый SpeechKit и адаптивные уточняющие вопросы в режиме голосового тьютора.
- Аналитика пробелов группы для преподавателя.
- Политики согласия, хранения и удаления голосовых данных.

## 4. Матрица тестирования

### Автоматические проверки

| Область | Проверка |
| --- | --- |
| Авторизация | первый администратор, JWT, роли и запрет чужих попыток |
| Экзамен | назначение, скрытие следующих вопросов, порядок ответов |
| Аудио | тип, размер, сохранение, outbox-событие |
| AI-пайплайн | транскрипция → RAG → оценка → итог попытки |
| Explainability | реальные фрагменты RAG попадают в отчет |
| Safety | балл ограничен максимумом, низкая уверенность включает review |
| Readiness | endpoint показывает mock/real и конфигурацию компонентов |
| Frontend | TypeScript, production build, отсутствие runtime-ошибок |

### Браузерные сценарии

1. Гость видит ценность продукта, AI-пайплайн и честную маркировку демо.
2. Студент входит, открывает тренировку, начинает попытку и видит только текущий вопрос.
3. После обработки студент видит структурированный отчет, источники и статус уверенности.
4. Преподаватель видит свои тесты, материалы и конструктор.
5. Преподаватель открывает очередь спорных ответов и сохраняет итоговый балл с комментарием.
6. Студент повторно открывает попытку и видит отдельно AI-оценку и решение преподавателя.
7. Экзаменуемый видит только назначенный экзамен.
8. Администратор видит пользователей, попытки, очередь и ошибки.
9. Интерфейс проверяется на desktop и узком viewport без горизонтального разрушения.

## 5. Сценарий показа на конференции (4 минуты)

1. **Проблема, 30 секунд:** преподаватель физически не может дать каждому студенту подробную обратную связь по устному ответу.
2. **Материалы и рубрика, 40 секунд:** показать вопрос, критерии и конспект преподавателя.
3. **Ответ студента, 50 секунд:** открыть назначенную тренировку и записать голос.
4. **Как работает AI, 40 секунд:** SpeechKit → RAG → YandexGPT, без передачи ключей в браузер.
5. **Объяснимый результат, 60 секунд:** балл, расшифровка, сильные стороны, пробелы, следующий шаг, источники и human review.
6. **Доказательства, 30 секунд:** автотесты, результаты пилота, время/стоимость обработки.
7. **Развитие, 30 секунд:** адаптивный голосовой тьютор и аналитика группы.

## 6. Критерий готовности

Версия готова к подаче, когда backend-тесты и frontend build проходят, девять браузерных сценариев проверены, реальный AI smoke-test документирован, публичный стенд доступен по HTTPS, а демонстрация воспроизводится как в live-, так и в резервном видео-режиме.
