# TuneAI — карта переноса согласованного дизайна

Этот документ связывает статический прототип с текущим React-интерфейсом. Он не является разрешением менять production: перенос начинается только после визуального согласования направления.

Статический пример намеренно проверяет направление на самом частом пути: пользователь выбирает тест, отвечает и получает понятную обратную связь. Экраны автора, проверяющего и администратора нужно согласовать отдельным вторым прототипом до их production-рефакторинга.

## Инварианты переноса

- API-контракты, permission checks и существующие React handlers не меняются вместе с визуальным рефакторингом.
- Сохраняются фирменные цвета `#fffdf4`, `#111111`, `#ffcc13`, `#e3d9c1`, `#f7f2e3`, `#147a39`.
- В learner-flow используется одна кириллическая гарнитура `Golos Text` для интерфейса, вопросов и расшифровки; отдельная display-пара и моноширинный tech-декор исключены.
- Иконки остаются в существующем `lucide-react`; emoji не используются как элементы управления.
- На desktop используется sidebar, на телефоне — нижняя навигация максимум из пяти ключевых разделов. Редкие действия уходят внутрь экрана или профиля.
- Один экран получает одно главное действие. Вторичные действия не конкурируют с ним цветом и размером.
- Второстепенные критерии, рубрики, альтернативные способы ответа и расшифровки раскрываются по запросу; на mobile список и детали задания показываются последовательно.
- Внутри задания вопросы остаются нелинейными: студент видит состояния `ответ готов`, `черновик`, `не начат`, `отложено` и может вернуться к любому вопросу.
- Статичные экраны не имитируют real-time телеметрию зелёными точками или «обновлено сейчас»; рекомендации не оформляются как отдельные цветные callout-карточки.
- Обзор не получает KPI-полосы ради заполнения пространства: счётчик или прогресс живёт только рядом с объектом, который он описывает.
- Верхнеуровневые секции по умолчанию разделяются линиями, отступами и типографикой; карточка используется только когда она объясняет самостоятельный интерактивный объект.
- Loading, empty, error, disabled и success states проектируются до подключения реальных данных.
- Все формы сохраняют видимые labels, keyboard navigation, focus states и target size не меньше `44×44 px`.

## Порядок production-работ после согласования

1. Зафиксировать текущий UI в archive branch и annotated tag от коммита `d502288`.
2. Выделить semantic tokens и базовые primitives, не меняя данные и бизнес-логику.
3. Перенести публичный лендинг и авторизацию; проверить desktop/mobile и реальные auth errors.
4. Перенести общий shell с role-aware навигацией и deep-link состояниями.
5. Перенести learner-flow: overview → tests → attempt → result/history.
6. Сделать и согласовать второй HTML-прототип для creator/reviewer/admin workflows.
7. Перенести builder, materials, review и admin небольшими независимыми итерациями.
8. Прогнать lint, frontend tests, production build, keyboard/a11y smoke-test и visual QA на реальных данных.

## Импорт лекции

### Что уже можно подключить

Текущие `uploadPresentation`, `generateFromPresentation` и `acceptPresentationCandidate` уже покрывают загрузку PDF/PPTX, выбор сегментов, генерацию и принятие кандидатов. Новый экран не требует менять этот контракт: он последовательно раскладывает существующие операции по четырём этапам и сохраняет обычный черновик assessment конечной точкой.

### Граница YouTube v1

- только публичное отдельное видео;
- только доступные ручные или автоматические субтитры;
- выбор языка, временных фрагментов и ссылка на точное время;
- предпросмотр расшифровки до генерации;
- смешанные типы вопросов в общем редакторе кандидатов;
- плейлисты, приватные видео и анализ изображения остаются вне первой версии;
- если субтитров нет, SpeechKit запускается только после показа длительности, примерной стоимости и отдельного подтверждения.

### Кэш

Извлечённый материал нужно хранить по стабильному идентификатору источника и его версии. Для YouTube это `video_id + язык + версия субтитров`, для файла — хеш содержимого. Сегменты, временные метки и текст переиспользуются при повторной генерации; платное распознавание аудио не запускается повторно для неизменившегося источника.

## Архив UI v1

После согласования, перед первым production-коммитом:

```bash
git branch archive/ui-v1-2026-08-23 d502288
git tag -a ui-v1-before-redesign d502288 -m "Archive TuneAI UI before UX redesign"
git push origin archive/ui-v1-2026-08-23 ui-v1-before-redesign
```

Команды не выполняются автоматически: создание и push архива должны быть частью согласованного production-этапа.
