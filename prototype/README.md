# TuneAI — анти-slop прототип

Отдельный статический прототип будущего интерфейса. Он не импортируется во frontend и не меняет production UI. В прототип входят публичный лендинг и личный кабинет студента.

## Что изучено

- текущая production-страница `https://tuneai.vnshk.ru/` в viewport 1440×900 и 390×844;
- актуальная ветка `dev`: `frontend/components/TuneAIApp.tsx`, `frontend/app/styles.css` и runtime-конфигурация;
- существующий скриншот `docs/screenshots/landing.png`;
- desktop и mobile breakpoints, навигация, формы и post-login app shell.

## Почему текущий UI выглядит AI-generated

1. Масштаб используется вместо иерархии: заголовки 88–190 px и декоративный wordmark до 360 px забирают внимание у самого продукта.
2. Почти любой фрагмент превращён в одинаковую карточку: pipeline, аудитории, преимущества, сценарии, действия и статусы визуально спорят друг с другом.
3. Pill-кнопки используются для большинства действий и перестают обозначать приоритет.
4. На старой production-странице форма регистрации конкурирует с главным сообщением уже в первом экране.
5. На mobile основная навигация скрывается, а контент просто складывается в длинную колонку.
6. Термины `SpeechKit`, `RAG` и `YandexGPT` объясняют реализацию раньше, чем пользователь понял результат.
7. Внутренний интерфейс уменьшает desktop sidebar до последовательности колонок, но не вводит отдельную мобильную модель навигации.

## Направление прототипа

- Сохраняются исходные цвета: `#fffdf4`, `#111111`, `#ffcc13`, `#e3d9c1`, `#f7f2e3` и `#147a39`.
- Основное сообщение: не «мы используем AI», а «вы отвечаете и понимаете, что улучшить».
- Один главный CTA на экран; вторичные действия выглядят вторичными.
- Фирменный объект — лента ответа с вопросом, расшифровкой и критериями.
- Вместо сетки feature-карточек — одна последовательность действий и один содержательный результат.
- Рекомендации встроены в документ через обычную типографику и разделители, без жёлтых callout-карточек.
- Псевдо-live точки «обновлено / готово / проверено» не используются; состояние показывается только когда оно влияет на действие пользователя.
- Обзор не начинается с декоративной полосы KPI: прогресс показан только рядом с заданием, к которому он относится.
- «Сегодня» содержит один текущий вопрос и одну основную кнопку; следующие задания вынесены в короткий линейный список.
- После выбора задания открывается его список вопросов: студент может продолжить черновик, начать любой вопрос или отложить неудобный вопрос на потом.
- Критерии, текстовая альтернатива, рубрика и расшифровка открываются по запросу, а не конкурируют с главным действием сразу.
- Авторский импорт лекции разбит на четыре настоящих этапа: источник → фрагменты → настройки → проверка вопросов.
- Крупные смысловые блоки собраны разделителями и ритмом, а не одинаковыми скруглёнными контейнерами.
- Поля имеют видимые labels; touch targets не меньше 44 px; фокус видим; reduced motion поддерживается.
- На mobile сценарии не исчезают и помещаются без горизонтального скролла.

## Типографика личного кабинета

- `Golos Text` используется и для интерфейса, и для учебного содержания. Одна кириллическая гарнитура уменьшает декоративный шум и лучше держит длинные технические формулировки.
- От отдельной display-гарнитуры и serif для вопросов отказались: иерархию создают размер, вес и интервалы, а не «дизайнерская» пара шрифтов.
- Моноширинный шрифт убран. Для таймкодов и оценок используются обычные цифры с `font-variant-numeric: tabular-nums`.
- Вес заголовков снижен, а чрезмерно отрицательный трекинг смягчён.

## Как открыть

```bash
python3 -m http.server 4173 --directory prototype
```

Затем открыть `http://127.0.0.1:4173/`.

- `index.html` — лендинг, сценарии и форма входа;
- `dashboard.html` — обзор, задания со свободным выбором вопросов, прохождение вопроса, разбор результата и авторский импорт лекции;
- `IMPLEMENTATION.md` — карта соответствия текущим React-компонентам и безопасный порядок production-переноса;
- переход между экранами доступен через боковую навигацию на desktop и нижнюю навигацию на mobile.

## Проверка прототипа

- Learner-flow и импорт лекции проверяются в viewport `1280×800`, `768×900`, `844×390`, `375×812` и `320×568`.
- Горизонтального переполнения нет; все видимые интерактивные зоны не меньше `44×44 px`.
- Проверены последовательность заголовков, labels полей, accessible names, уникальность ID и работа клавиатурного фокуса.
- Навигация, смена сценария, окно входа, запись ответа и уведомления работают без подключения backend.
- Поддерживается `prefers-reduced-motion`; нижняя мобильная навигация учитывает safe-area.
- Концепт намеренно остаётся в светлой фирменной теме: dark mode не добавлялся, чтобы не менять согласованную палитру до отдельного решения.


Создание и отправка archive branch/tag выполняются только перед production-реализацией, после согласования прототипа.
